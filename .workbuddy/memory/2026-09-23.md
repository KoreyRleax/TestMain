## TestMain 仓库（Desktop\1）本地与远程不一致的诊断

**现象**：用户反馈"工作区内容与远程不一致，但提交已经是最新的，拉取也不行"。

**实测事实**
- 仓库 `C:\Users\59538\Desktop\1`，Remote 两个：
  - `origin` → https://github.com/KoreyRleax/TestMain.git（fork）
  - `main`   → https://github.com/rbl-sz/TestMain.git（上游）
- `refs/heads/main` = `7bd61bd`，`refs/remotes/origin/main` = `570bacf`
- `ls-remote` 两个 remote 的 `refs/heads/main` 均 = `570bacf`（与本地 tracking ref 一致，**引用不陈旧**）
- 工作区干净：`status --porcelain -uall` 空、`diff HEAD` 空、`ls-files -v` 为 `H`（无 assume-unchanged 位）
- 内容差异：`HEAD:1.txt` = `33333333333`，`origin/main:1.txt` = `22222222222222222`
- `status -sb` = `## main...origin/main [ahead 2]`
- reflog：`7bd61bd HEAD@{0}: pull: Merge made by the 'ort' strategy.` ← 17:39 已 pull 过一次

**根因（两条）**
1. 本地有 2 个提交从未推送（`6f78cae "3"` + merge `7bd61bd`）。用户做的操作是 **pull**，而 pull 方向是"远程→本地"，永远送不出本地提交 → 报 `Already up to date.`；`commit ≠ push`，"status 干净 + log 最新"只说明本地没落下东西，与远程无关。
2. `remote` 名为 `main`，与本地分支 `main` 同名 → `warning: refname 'main' is ambiguous`。手写 `git pull main` / `git push main` 时 `main` 会被解析成 **remote 名**（rbl-sz 上游），拉到/推到另一个仓库。

**处置建议（用户本地执行）**
- `git push origin main`（显式写 origin，避开同名歧义）
- `git remote rename main upstream`（消除歧义，符合 fork 惯例）
- 若要反向对齐（以远程为准）：`git reset --hard origin/main`（破坏性，需用户确认）
